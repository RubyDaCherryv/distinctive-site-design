# distinctive-site-design

Skill для AI-агента: делает сайты, которые выглядят придуманными под конкретную задачу, а не собранными из шаблона. Агент сначала определяет предмет, аудиторию и цель страницы, потом выбирает визуальное направление, пишет дизайн-план, проверяет его на «типовой AI-look» и только после этого верстает. Отдельный блок правил делает вёрстку адаптивной под iPhone Duo (складной iPhone от Apple).

## Что решает

Обычный запрос «сделай лендинг» даёт узнаваемый результат: тёплый кремовый фон с засечками, тёмная тема с одним кислотным акцентом, три одинаковые карточки, нумерация «01 / 02 / 03» без смысла. Skill заставляет агента принимать решения под конкретный бриф: цвет, шрифты, композицию и один запоминающийся элемент страницы.

## Как работает

Агент идёт по шагам из [`SKILL.md`](SKILL.md):

| Шаг | Что происходит |
|---|---|
| 0. Бриф | Фиксируются предмет, аудитория, единственная задача страницы, реальный контент |
| 1. Цель | Определяется тип сайта: продающий, имиджевый, визитка, событие, витрина продукта, редакционный |
| 2. Направление | Три кандидата из библиотеки направлений, выбор одного с обоснованием |
| 3. План | Палитра из 4-6 именованных цветов, роли шрифтов, ASCII-схема раскладки, «подпись» страницы, движение |
| 4. Критика | План сверяется с типовыми шаблонами и переписывается, если совпал с ними |
| 5. Вёрстка | Код строго по плану, правила адаптива и iPhone Duo с первой строки |
| 6. Проверка | Скриншоты на разных ширинах (если среда позволяет), чек-лист, убрать одну лишнюю деталь |

Цель сайта меняет логику страницы, а не только оформление: у продающей страницы есть последовательность убеждения, у имиджевой ставка на атмосферу и темп, у визитки на быстрое считывание с телефона.

## iPhone Duo

Правила в [`references/iphone-duo.md`](references/iphone-duo.md) переводят нативные рекомендации Apple на язык веба:

- два режима вёрстки (компактный и широкий), а не отдельный макет под каждую позу устройства;
- никаких проверок ориентации и устройства, только содержимое, контейнерные запросы и доступное пространство;
- широкие, но невысокие экраны: герой без жёсткой высоты, главное действие видно без прокрутки;
- независимые левый и правый `safe-area`, потому что системные элементы могут уезжать на сторону;
- центральная полоса под возможный сгиб без кнопок, полей и навигации (текст и фон могут её пересекать);
- живое изменение размера без потери прокрутки, фокуса и состояния.

Что здесь проверено, а что нет:

- Правила опираются на Apple Tech Talks и пересказы HIG. Страница HIG требует JavaScript и при подготовке skill не читалась напрямую.
- Отдаёт ли Safari на iPhone Duo информацию о сгибе веб-страницам, в источниках не подтверждено. Поэтому правило про зону сгиба сделано как эвристика, которая работает и без такой информации.
- Нативные API Apple (`reservedRegion`, arrangement views, вертикальные бары) сайтам недоступны и приведены только как источник логики.

## Установка

Claude Code, на уровне пользователя:

```bash
git clone https://github.com/RubyDaCherryv/distinctive-site-design ~/.claude/skills/distinctive-site-design
```

Или на уровне проекта: положите папку в `.claude/skills/` репозитория. Перезапустите сессию. Skill подхватывается по описанию задачи, вызывать его по имени необязательно. Другим агентам подойдёт любая схема, где они читают обычный Markdown: отдайте им `SKILL.md`, а файлы из `references/` агент откроет по ссылкам из него.

## Примеры запросов

```text
Сделай одностраничный сайт для Telegram-бота, который подбирает open-source проекты. Только фронтенд.
Нужен лендинг для мастерской по ремонту велосипедов, цель: записать на обслуживание.
Сайт-визитка для фотографа, должен нормально выглядеть на складном iPhone.
Перерисуй мою страницу так, чтобы она не выглядела как шаблон. Файл во вложении.
```
